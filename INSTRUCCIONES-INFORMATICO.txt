WEB VAYPATEL PROYECTOS — NOTAS PARA LA PUBLICACIÓN
==================================================

QUÉ ES
  PHP sin base de datos ni frameworks. La página (index.php) se genera en el
  servidor a partir de contenido.json, así que Google lee todo el texto.
  El contenido se edita desde un panel propio en /admin/ (basado en la idea del
  panel de la versión "comparativa v2", reescrito).
  Requisitos: PHP 7.4 o superior (probado en 8.3) con las extensiones GD, json,
  mbstring, session y fileinfo, y la función mail() activa.

PUBLICAR
  1. Subir TODO el contenido del ZIP a la raíz del dominio, manteniendo carpetas
     y los archivos ocultos .htaccess (raíz, img/, img/galeria/, incluir/,
     admin/datos/).
  2. Permisos de escritura para el usuario de PHP en:
       contenido.json · admin/datos/ (y admin/datos/copias/) · img/ · img/galeria/
     El resto puede quedar en solo lectura.
  3. Activar SSL. Después, descomentar en .htaccess el bloque "Forzar HTTPS y www".
  4. Entrar en https://www.vaypatel.com/admin/ con la contraseña provisional
     (se entrega aparte, no está en ningún archivo). El primer acceso obliga a
     cambiarla.

REPOSITORIO GITHUB
  admin/datos/clave.php NO está en el repositorio (es público): al publicar
  desde GitHub hay que subir ese archivo aparte o crear uno nuevo (ver abajo).

PANEL /admin/
  - Edita portada, cifras, servicios, acreditaciones, obras, referencias, fotos de
    la galería (pie, categoría, orden), empresa, clientes y contacto.
  - Sube fotos: se comprueban como imagen real, se vuelven a codificar en JPG
    (máx. 1600 px) con nombre generado. No se conserva el archivo original.
  - Cada guardado deja copia de la versión anterior en admin/datos/copias/
    (últimas 20) y se puede recuperar desde el panel.
  - Seguridad: contraseña con bcrypt (password_hash), token CSRF en todos los
    formularios, cookie de sesión HttpOnly/SameSite=Strict, caducidad a las 2 h
    sin actividad, bloqueo de 15 min tras 5 intentos fallidos por IP.
  - La contraseña y los intentos se guardan en admin/datos/*.php, que empiezan
    por "<?php exit; ?>": aunque se abran desde la web no muestran nada.
  - Si se olvida la contraseña: borrar admin/datos/clave.php y crear uno nuevo con
      php -r 'echo "<?php exit; ?>\n".json_encode(["hash"=>password_hash("NUEVA",PASSWORD_DEFAULT),"cambiar"=>true]);' > admin/datos/clave.php

FORMULARIO (enviar.php) Y ENVÍO DE CORREO
  - Cada consulta se envía al email de contacto del panel (a.arribas@vaypatel.com).
  - Validación, aceptación de privacidad obligatoria, campo trampa antispam, trampa
    de tiempo (menos de 3 s se descarta) y límite de un envío cada 30 s por sesión.
    Sin JavaScript redirige a /?envio=ok|datos|error#contacto. Los errores de envío
    quedan en el log de errores de PHP con el motivo.
  - Cómo se envía: incluir/correo.php, según admin/datos/correo.php (no está en el
    repositorio). Este servidor (Apache en AWS) no tiene mail(), así que hay que
    configurar una de las dos opciones siguientes. Las dos salen por Microsoft 365
    (donde está el correo de vaypatel.com), así que pasan SPF, DKIM y DMARC sin
    tocar los DNS. Otro proveedor SMTP (SES, Brevo…) exigiría registros DNS nuevos.

  OPCIÓN A · SMTP de Microsoft 365 (la más rápida de montar)
    1. Un buzón con licencia para enviar, p. ej. web@vaypatel.com.
    2. Activar "SMTP autenticado" en ese buzón (Centro de administración >
       Usuarios > el usuario > Correo > Administrar aplicaciones de correo) y
       que el inquilino no lo tenga bloqueado (Set-TransportConfig
       -SmtpClientAuthenticationDisabled o la excepción por buzón). No funciona
       si la cuenta tiene MFA obligatoria o "valores predeterminados de seguridad".
    3. admin/datos/correo.php (dos líneas):
         <?php exit; ?>
         {"modo":"smtp","host":"smtp.office365.com","puerto":587,"cifrado":"starttls","usuario":"web@vaypatel.com","clave":"CONTRASEÑA","remitente":"web@vaypatel.com"}
    Ojo: Microsoft desactiva por defecto esta autenticación (usuario y
    contraseña por SMTP) a finales de diciembre de 2026; un administrador puede
    volver a activarla, pero la retirará del todo más adelante. Para no depender
    de eso, mejor la opción B.

  OPCIÓN B · Microsoft Graph (recomendada a largo plazo; va por HTTPS)
    1. Microsoft 365: crear un buzón compartido web@vaypatel.com (no necesita
       licencia) o elegir el buzón desde el que se enviará.
    2. Entra ID > Registros de aplicaciones > Nuevo registro ("Web Vaypatel").
       Permisos de API > Microsoft Graph > Permisos de aplicación > Mail.Send >
       Conceder consentimiento de administrador.
       Certificados y secretos > Nuevo secreto de cliente. Anotar la fecha de
       caducidad: hay que renovarlo antes (si caduca, el formulario deja de enviar).
    3. Recomendado: limitar la aplicación a ese único buzón (Exchange Online:
       RBAC for Applications, o New-ApplicationAccessPolicy -AccessRight
       RestrictAccess -PolicyScopeGroupId web@vaypatel.com).
    4. admin/datos/correo.php (dos líneas):
         <?php exit; ?>
         {"modo":"graph","tenant":"ID_DEL_INQUILINO","cliente":"ID_DE_LA_APLICACION","secreto":"SECRETO","buzon":"web@vaypatel.com"}

  En las dos opciones:
    - admin/datos/ no es accesible desde la web (.htaccess) y el archivo empieza
      cortando PHP, así que no muestra nada aunque se abra.
    - Probar: php incluir/probar-correo.php a.arribas@vaypatel.com (desde SSH),
      o enviar una consulta desde el formulario. Si falla, el motivo exacto queda
      en el log de errores de PHP (y lo muestra el script de prueba).
    - Salida a internet necesaria desde el servidor: puerto 587 (opción A) o 443
      (opción B). El puerto 25, que AWS limita, no se usa.

  - PROBAR tras publicar: enviar una consulta y comprobar que llega.

SERVIDOR NGINX (los .htaccess no aplican; equivalente mínimo)
  index index.php index.html;
  error_page 404 /404.html;
  location ~ ^/(incluir|admin/datos)/ { deny all; }
  location ~ ^/img/.*\.(php|phtml|phar)$ { deny all; }
  location ~ \.tmp- { deny all; }
  location = /INSTRUCCIONES-INFORMATICO.txt { deny all; }
  location = /LEEME.txt { deny all; }
  + redirección 301 a https://www.vaypatel.com

DOMINIO, SUBDOMINIOS Y CORREO
  Los DNS ya están configurados y no hay que cambiarlos: vaypatel.com,
  www.vaypatel.com, vaypatel.es y www.vaypatel.es apuntan al hosting, y el
  correo está en Microsoft 365 (no tocar MX ni registros de Microsoft).
  No hacen falta subdominios: el panel está en /admin/ dentro de la web.
  La dirección oficial es https://www.vaypatel.com (es la que indica la etiqueta
  canonical a Google). Opcional pero recomendado: activar en .htaccess el bloque
  "Dirección única" para que las otras tres redirijan a esa.
  Formulario: con las opciones A o B (ver FORMULARIO) no hace falta ningún
  cambio de DNS.
  Página 404: 404.html (diseño de la web). En Apache ya está en .htaccess;
  en Nginx: error_page 404 /404.html;

HORARIO
  El texto del horario se edita en el panel (Contacto). No se publica en los
  datos estructurados hasta confirmar los días de atención; cuando se
  confirmen, puede añadirse openingHoursSpecification en index.php.

SEO YA INCLUIDO
  title y description, canonical, Open Graph y Twitter (img/compartir.jpg), datos
  estructurados LocalBusiness (dirección, zona de servicio y servicios), robots.txt (excluye /admin/), sitemap.xml, 404.
  Tras publicar: alta en Google Search Console, enviar /sitemap.xml, y crear o
  vincular la ficha de Google Business Profile.

TIPOGRAFÍAS
  Alojadas en el propio servidor (assets/fuentes/, woff2, subconjunto latino;
  licencia SIL OFL 1.1, ver LICENCIA.txt). No se hacen peticiones a Google.
  index.php incluye estilos.css y fuentes.css en línea para que la página
  pinte sin esperar a hojas externas: tras editar estilos.css no hay que
  hacer nada más.

IMÁGENES
  Cada foto puede tener al lado una versión .webp con el mismo nombre (y una
  de 480 px, nombre-480.webp, para las fotos grandes). La web usa la WebP si
  existe y la JPG si no. El panel ya genera la .webp al subir fotos.

HOSTING (el actual de vaypatel.com, gestionado por el informático)
  - Necesita PHP 8.0 o superior (mejor 8.3) con gd (con soporte WebP),
    mbstring, fileinfo y session; exif es opcional. Y mail() activo o SMTP.
  - Apache o LiteSpeed leen el .htaccess tal cual. Si es Nginx, ver abajo.
  - Dominios que sirve: vaypatel.com, www.vaypatel.com, vaypatel.es y
    www.vaypatel.es. El certificado SSL debe cubrir los cuatro. Después,
    el bloque "Dirección única" del .htaccess redirige todos a
    https://www.vaypatel.com (una sola dirección: mejor para Google).
  - Privacidad: privacidad.html (apartado 5) indica Amazon Web Services (servidor
    en Irlanda) y Microsoft 365 (correo). Si cambia el alojamiento, actualizarlo.
  - Al terminar la subida, cerrar el FTP (o limitarlo por IP) y cambiar su
    contraseña: se ha compartido por correo.
